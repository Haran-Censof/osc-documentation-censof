Each module's SDS defines its use cases in a transaction table: ID, name, main flow, alternative scenarios, actor, input, output and UI reference. This section presents those tables as they are written. Nothing is summarised or inferred.

Open a module to explore its use cases as an interactive flow. Each flow links to the screens the SDS maps to it, and every database table and field the SDS names is checked against the live `oscp` schema.

## How this page stays correct

| Source | Extracted by | Output |
|---|---|---|
| SDS Word documents (one per module) | `scripts/extract-sds.py`, `scripts/extract-usecases.py` | `data/usecases/` |
| Running system (routes, database schema) | `scripts/extract-facts.mjs` | `data/facts/` |

Re-run the scripts when an SDS or the code changes; the pages update from the data.
